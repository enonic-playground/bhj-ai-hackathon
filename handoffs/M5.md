### Summary

Every piece extends the existing DOM-free-simulation/shell/renderer architecture rather than adding a parallel one, matching D020's boundary: no gameplay rule, timing, collision or score value changed.

**Reduced motion.** `src/render/motion.ts` factors the four decorative canvas effects — the D015 ball hue cycle, the power-pellet pulse, the frightened-expiry flash, the protection-ring pulse — into pure functions taking a `reducedMotion` boolean, so they are unit-testable without a canvas (`tests/motion.test.ts`); `MazeRenderer` calls them through one `setReducedMotion()` setter. `src/app/reducedMotion.ts`'s `ReducedMotionWatcher` wraps `matchMedia('(prefers-reduced-motion: reduce)')` including its `change` event, so a runtime OS change takes effect without a reload; `src/styles.css` adds a matching global CSS override for any transition/animation. Nothing here touches speed, timers, input, collision or scoring.

**Layout and focus.** `#app`'s safe-area padding now covers all four insets, not only the bottom; a new `.pwa` block (styles alongside the existing overlay/panel rules) holds the install/offline status without ever taking focus. The existing 360 × 640 stacked layout, 820 px+ two-column layout, focus management and 44 px targets (all M1–M4 work) are otherwise unchanged and re-verified rather than rebuilt; new coverage (below) exercises landscape, an eight-letter word, a long category, several misses, a five-digit score, the earned-life badge, and both of M4's newer result panels, none of which M1–M4's own suites happened to exercise together.

**Manifest and icons.** `public/manifest.webmanifest` (relative `start_url`/`scope`/icon paths, so it resolves correctly at the origin root or a subpath) and `public/icons/*.png`, generated by `scripts/generate-icons.mjs` — a hand-rolled PNG encoder (Node's own `zlib.deflateSync`, a hand-written CRC32) with no image-processing dependency, drawing this project's own established player-disc/ball-ring shapes rather than sourced artwork. `index.html` links the manifest, icons and a `theme-color`.

**Service worker and offline.** `sw/service-worker.template.js` is the worker's source; `vite.config.ts`'s `hacmanServiceWorkerPlugin` (Vite's own `configResolved`/`closeBundle` hooks, Node's built-in `fs`/`crypto` — no new dependency) fills in the real, hashed precache list from what the production build actually wrote and a version hash derived from that list plus `index.html`'s own content, writing `dist/sw.js` only when `mode === 'production'`. Every cached URL is relative to the worker's own script location, so the same output works at the origin root or a subpath with no build-time path knowledge. `src/app/pwa.ts` (DOM/service-worker wiring) and `src/app/pwaStatus.ts` (pure text/classification helpers, unit-tested in `tests/pwaStatus.test.ts`) register the worker only in the ordinary production build (`import.meta.env.PROD && !__TEST_FIXTURES__`) and reflect real lifecycle events as a quiet title-screen status line, never claiming readiness from registration alone.

**Safe updates.** The worker never calls `self.skipWaiting()` or `clients.claim()` anywhere, which alone is what makes the native waiting lifecycle work: a new version installs into its own cache and sits `waiting` until every client controlled by the previous version has closed, entirely through the platform's default behaviour. A failed/partial `cache.addAll()` during install rejects atomically, leaving the previously active version untouched. Cache names are namespaced by the worker's own `registration.scope` path, so an unrelated app at a different subpath on the same origin cannot collide with this app's cache cleanup.

**A real bug the test suite caught.** While testing offline reload, the app's own JS/CSS (loaded with `crossorigin`, so requested with an `Origin` header) failed to be served from cache even though the exact same URL was demonstrably present in `CacheStorage`, because `vite preview`'s static server sends `Vary: Origin` and the worker's own internal `cache.addAll()` fetch did not reproduce that header identically. Fixed by matching with `{ ignoreVary: true }` everywhere (this cache only ever holds the worker's own precached output, never negotiated third-party content, so ignoring `Vary` is the correct general policy, not a narrow workaround). See [D021](../DECISIONS.md#d021--m5-implementation-choices).

**A new, narrow fixture parameter.** `testBankWord=<index>` (`src/app/fixture.ts`) pins every level's word to the real 50-entry `WORD_BANK` instead of the 8-entry `SEED_WORDS` list `testWord`/`testWords` already use — added because `SEED_WORDS`'s longest entry is 7 letters, so no existing parameter can render a genuine eight-letter word/category, and dozens of committed M2–M4 tests depend on `testWord`/`testWords`' exact existing indices. `testWord`/`testWords` and every test using them are unchanged.
